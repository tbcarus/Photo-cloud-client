# 17. Open Questions

> Аудит As-Is Android-клиента PhotoCloud. Дата: 2026-09-10, HEAD `2b9ab69`.
> Здесь — то, чего нельзя узнать из кода. Ответы не придумываются.
> Раздел A — продуктовые решения (к владельцу продукта). Раздел B — факты, которые нужно проверить запуском на устройстве. Раздел C — связь с серверными открытыми вопросами (`client-handoff/08-client-relevant-open-questions.md`).

---

## A. Продуктовые вопросы

### Модель синхронизации

| # | Вопрос | Что видно в коде | От ответа зависит |
| --- | --- | --- | --- |
| Q1 | Должна ли синхронизация быть **полностью автоматической**, или нужна кнопка «Синхронизировать сейчас» и ручной повтор? | Ручные кнопки удалены (Stage 5J.2); остались только observer и periodic | UI Files, политика retry, F1/A2 |
| Q2 | Что делать с фото, **удалённым локально** после загрузки: backup (оставить на сервере), mirror (удалить на сервере), гибрид (пометить)? | Строка удаляется из Room, сервер не уведомляется; `LOCAL_DELETED` объявлен, но не используется | нужен ли `DELETE /files/{id}`, статус `LOCAL_DELETED`, отображение |
| Q3 | Должен ли пользователь **удалять файлы с сервера** из приложения? | Нет ни одного экрана серверного содержимого | объём UI, хранение `serverFileId` для всех файлов |
| Q4 | Нужны ли **видео**? | Только `Images`; guard `image/*` | разрешения, коллекции MediaStore, лимит 100 MiB |
| Q5 | Какие **папки устройства** синхронизировать: только `DCIM/`, или также `Pictures/`, `Screenshots`, мессенджеры; должен ли выбирать пользователь? | Фильтр `DCIM/%` захардкожен (Stage 5I) | настройки, фильтр MediaStore |
| Q6 | Должна ли синхронизация работать **только по Wi-Fi** / только при зарядке? | `NetworkType.CONNECTED`; periodic — battery not low | constraints, настройки |
| Q7 | В какую **серверную папку** загружать: всегда `CAMERA`, выбор пользователя, соответствие локальным папкам? | Только `CAMERA` | pre-check по нескольким папкам, хранение `folderId` |
| Q8 | Что делать с **изменённым локально** файлом (поворот, редактирование): загрузить как новый, заменить старый (удалить прежний на сервере), игнорировать? | Загружается как новый; прежняя серверная запись остаётся, связь теряется | детектор изменений, вызовы `DELETE` |
| Q9 | Нужно ли удалять или сохранять **локальный индекс при logout**? Поддерживается ли смена аккаунта на одном устройстве? | Индекс не очищается и не привязан к аккаунту (D1) | схема Room, процедура logout |
| Q10 | Что делать при **смене сервера**: сбрасывать индекс, хранить индексы по серверам? | Индекс общий | то же |
| Q11 | Нужно ли **показывать содержимое облака** (галерея, миниатюры, скачивание)? | Нет | `GET /files`, download, кэш миниатюр |
| Q12 | Что делать с **файлами > 100 MiB**: не ставить в очередь, предупреждать, сжимать? | Отправляются и получают `FAILED(HTTP_413)` | фильтр при scan, UI |
| Q13 | Какова **политика retry**: сколько попыток, какие ошибки повторять вручную; должны ли `PERMISSION` и `FILE_NOT_FOUND` восстанавливаться автоматически после возврата доступа? | Только `CHECKSUM_IO` ≤ 3; остальное терминально; transient — бесконечно | `FailureReason`, лимиты, UI |
| Q14 | Должна ли загружаемая копия быть **побайтовым оригиналом**, включая GPS (`ACCESS_MEDIA_LOCATION`)? Допустима ли передача геопозиции на сервер? | Разрешение не запрашивается | разрешения, приватность |
| Q15 | Нужны ли **уведомления / foreground-прогресс** для долгой первичной синхронизации? | Нет | foreground service, UX |
| Q16 | Является ли требованием **работа после перезагрузки без открытия приложения**? | Не работает (C1) | инициализация приложения |
| Q17 | Нужна ли работа **через Интернет** (HTTPS, доменное имя, reverse proxy) или только в LAN? | Только `http://IPv4:port` | экран Network, network security config |
| Q18 | Нужен ли `serverFileId` для **всех** `SYNCED`-файлов (под будущие download/delete)? | Не заполняется для найденных pre-check | обратная синхронизация через `GET /files` |
| Q19 | Нужна ли **история синхронизаций** / время последней успешной синхронизации? | Только in-memory последний статус | хранение, UI |
| Q20 | Какой должен быть **сценарий регистрации и восстановления пароля** в приложении: экран «подтвердите email», предупреждение о невозможности resend, ввод кода сброса? | Нет | экраны auth |
| Q21 | Приемлемо ли поведение при **partial photo access** (Android 14): синхронизировать только выбранные фото? | Не обрабатывается | разрешения, stale-удаление |
| Q22 | Каково назначение вкладок **Profile** и **Settings**? | Заглушки; профиль показан на вкладке Login | навигация |
| Q23 | Должны ли отладочные элементы (кнопки «Test», «Test Auth», диалог сервера на старте, сырые счётчики) остаться в release? | Присутствуют | UI |
| Q24 | Что показывать пользователю при **истечении сессии** (7 дней): уведомление, переход на вход? | Ничего | auth UX |
| Q25 | Поддерживается ли сценарий **нескольких устройств** одного пользователя и нужно ли показывать файлы, загруженные с другого устройства? | Нет обратной синхронизации | `GET /files`, polling |

## C. Связь с серверными открытыми вопросами
